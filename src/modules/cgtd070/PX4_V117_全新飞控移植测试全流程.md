# CGTD070吊舱PX4 v1.17全新飞控移植与测试全流程

## 1. 文档目的和适用范围

本文用于把`cgtd070`吊舱串口模块移植到一份全新的PX4源码和飞控上，
完成编译、烧录、无吊舱软件测试、吊舱实物测试、遥控器测试及开机自启。

当前已验证基准：

- PX4-Autopilot v1.17.0。
- CUAV V6X v2，构建基础目标`cuav_fmu-v6x_default`。
- CGTD070协议V2.12。
- 串口115200 baud、8N1、非阻塞。
- 飞控每40 ms发送一帧，即25 Hz、每帧44字节。
- 吊舱反馈帧64字节。
- 独立PX4 Task，不使用Work Queue。
- 无STL容器、异常和RTTI；协议缓冲区固定大小。

如果更换PX4大版本、飞控型号或吊舱协议版本，必须重新完成编译和台架验证。

## 2. 交付物

模块目录应至少包含：

```text
cgtd070/
├── CMakeLists.txt
├── Kconfig
├── library/
│   ├── include/cgtd070_core.hpp
│   ├── include/cgtd070_protocol_types.hpp
│   └── src/cgtd070_core.cpp
├── drivers/serial/
│   ├── cgtd070_serial_driver.hpp
│   └── cgtd070_serial_driver.cpp
├── px4_module/
│   ├── cgtd070_app.hpp
│   └── cgtd070_app.cpp
├── msg/Cgtd070Status.msg
└── tests/test_cgtd070_core.cpp
```

各目录职责：

- `library`：与PX4、串口和UDP无关的协议打包、解包和内部缓冲区。
- `drivers/serial`：PX4/NuttX串口打开、配置、非阻塞读写及错误统计。
- `px4_module`：独立Task、uORB订阅发布、25 Hz调度、遥控器逻辑和NSH命令。
- `msg`：提供给制导等PX4模块的最小uORB消息。
- `tests`：主机端协议核心测试。

## 3. 安全和准备要求

首次测试必须在台架上进行：

- 飞控保持未解锁。
- 电机断电或拆除桨叶。
- 吊舱固定牢靠并留出转动空间。
- TTL串口必须共地，TX/RX交叉连接。
- 先确认飞控串口电平与吊舱兼容，禁止把RS-232电平直接接到TTL口。
- 不确定供电定义时，不连接串口线束中的电源脚，只连接TX、RX、GND。
- 不要随机试写`/dev/ttySx`，某些设备可能连接GPS、接收机或遥测电台。

准备软件：

- Ubuntu虚拟机或原生Ubuntu。
- 完整Git版PX4-Autopilot v1.17.0及全部子模块。
- PX4官方工具链。
- QGroundControl。
- USB数据线和SD卡。
- 最终硬件验证建议准备USB-TTL或逻辑分析仪。

## 4. 检查全新PX4源码

以下示例源码路径为：

```text
/home/xy-shiqi/PX4-Autopilot-1.17.0
```

进入源码并检查版本：

```sh
cd ~/PX4-Autopilot-1.17.0
git describe --always --tags
git status --short
git submodule status --recursive | grep -E '^[-+U]'
```

预期版本：

```text
v1.17.0
```

最后一条命令没有输出，表示没有缺失、错位或冲突的子模块。

ZIP源码通常没有`.git`和完整子模块，不建议用于正式开发移植。

## 5. 先编译未经修改的基线固件

先证明PX4源码、工具链和板级目标本身正常，再加入吊舱模块。

CUAV V6X：

```sh
cd ~/PX4-Autopilot-1.17.0
make cuav_fmu-v6x_default
```

```text

```

```text

```

例如`boards/cuav/fmu-v6x/default.px4board`对应
`cuav_fmu-v6x_default`。

## 8. 注册Cgtd070Status uORB消息

把消息定义复制到PX4根消息目录：

```sh
cd ~/PX4-Autopilot-1.17.0
cp src/modules/cgtd070/msg/Cgtd070Status.msg \
   msg/Cgtd070Status.msg
```

在`msg/CMakeLists.txt`的消息列表中加入：

```text
Cgtd070Status.msg
```

检查：

```sh
grep -n "Cgtd070Status.msg" msg/CMakeLists.txt
ls -l msg/Cgtd070Status.msg
```

消息只发布制导需要的四项：

```text
uint64 timestamp
float32 los_az_rate
float32 los_el_rate
float32 gimbal_roll
float32 gimbal_pitch
```

注意：当前`gimbal_roll`按项目要求命名，但实际承载协议中的吊舱方位/方位
框架角；`gimbal_pitch`承载俯仰框架角。协议核心仍然完整解包其他字段。

## 11. 烧录自定义固件

QGC方式：

1. 飞控只通过USB供电，断开电池和其他可能影响USB枚举的连接。
2. 打开QGC的固件页面。
3. 按提示拔下并重新插入飞控。
4. 选择“高级设置/自定义固件文件”。
5. 选择`cuav_fmu-v6x_cgtd070.px4`对应的实际生成文件。
6. 等待擦除、烧写、校验和重启全部完成。

也可尝试PX4命令行上传：

```sh
make cuav_fmu-v6x_cgtd070 upload
```

烧录后在MAVLink Console执行：

```text
help
```

命令列表中应出现：

```text
cgtd070
```

若不存在，通常是选错固件、板级配置未启用或烧录未成功。

## 12. 选择并检查物理串口

当前默认设备为：

```text
/dev/ttyS3
```

但换飞控后绝不能直接假定仍是`ttyS3`。先根据飞控手册确认外部接口和
PX4设备节点映射，再检查是否被其他模块占用：

```text
mavlink status
gps status
uxrce_dds_client status
```

同一串口不能同时被MAVLink、GPS、DDS客户端和`cgtd070`使用。

当前串口驱动配置固定为：

```text
115200 baud, 8 data bits, no parity, 1 stop bit
```

物理接线：

```text
飞控TX  → 吊舱RX
飞控RX  ← 吊舱TX
飞控GND ↔ 吊舱GND
```

## 13. 无吊舱的软件发送测试

即使没有连接吊舱，也可以验证Task、25 Hz调度、协议打包和串口驱动写入。

启动：

```text
cgtd070 start -d /dev/ttyS3
cgtd070 status
```

等待数秒后再次执行：

```text
cgtd070 status
```

预期：

- `mode: independent Task`。
- `TX`持续增加，约每秒增加25。
- `RX=0`，没有吊舱时正常。
- `IO errors=0`。
- `write errors=0`。
- `missed TX slots=0`或极少。

打开非空闲命令帧打印：

```text
cgtd070 trace on
cgtd070 track
cgtd070 center
cgtd070 cancel
```

预期每条命令打印一个完整44字节帧：

```text
track  → TX[02]=93
center → TX[02]=71
cancel → TX[02]=3b
```

同时确认：

```text
TX[00..01] = fb 2c
TX[43] = f0
```

空闲00H帧仍按25 Hz发送，但不会刷屏打印。

关闭调试：

```text
cgtd070 trace off
```

## 14. 吊舱实物收发测试

确认供电、接口电平和接线后连接吊舱，再启动模块：

```text
cgtd070 start -d /dev/ttyS3
cgtd070 status
```

预期：

- `TX`持续增加。
- `RX`持续增加。
- `parser bytes`持续增加。
- `parser ok`持续增加。
- `checksum=0`或偶发但不持续增长。
- `framing=0`或偶发但不持续增长。

查看uORB：

```text
listener cgtd070_status 5
```

应看到：

```text
los_az_rate
los_el_rate
gimbal_roll
gimbal_pitch
```

如果`RX`增长但`parser ok`不增长，优先检查协议版本、波特率、帧头帧尾和
校验算法。如果`RX=0`，优先检查接线、端口映射和吊舱是否实际发送反馈。

## 15. 验证飞控遥测段

44字节控制帧的8至37字节由PX4 uORB数据填充：

- `vehicle_attitude`：俯仰、横滚、航向。
- `sensor_gps`：UTC、经纬度、星数、MSL高度。
- `battery_status`：电池电压。
- `vehicle_global_position`与`home_position`：相对Home高度。

各订阅均为非阻塞。每个40 ms周期先创建全零遥测结构，只有新鲜、有效的
数据覆盖相应字段。任何来源缺失、超时或NaN时，对应协议字段为0，发送循环
仍保持25 Hz。

可以开启`cgtd070 trace on`后触发一次命令，检查打印帧8至37字节是否随
姿态、GPS和电池状态变化。软件打印证明帧已交给串口驱动，但最终引脚波形
仍应使用USB-TTL或逻辑分析仪确认。

## 16. 遥控器配置和测试

代码不绑定物理CH编号，只读取PX4标准化后的：

```text
manual_control_setpoint.aux1
manual_control_setpoint.aux2
```

因此换遥控器时一般只需要重新校准并调整QGC参数，不需要改代码或重新编译。

### 16.1 找原始通道

```text
listener input_rc 20
```

操作开关，找出`values[]`中变化的位置。数组从0开始，例如`values[4]`
对应CH5。

确认：

```text
rc_lost: false
rc_failsafe: false
```

### 16.2 检查功能冲突

```text
param show RC_MAP_*
```

确保计划使用的通道没有同时映射到飞行模式、解锁、返航、终止或其他关键
飞行功能。

### 16.3 映射到固定AUX接口

以CH5三段开关、CH6按钮为例：

```text
param set RC_MAP_AUX1 5
param set RC_MAP_AUX2 6
param save
```

### 16.4 检查标准化输入

```text
listener manual_control_setpoint 20
```

预期：

```text
valid: true
data_source: SOURCE_RC
aux1: approximately -1 / 0 / +1
aux2: approximately -1 / +1
```

### 16.5 检查吊舱命令

```text
cgtd070 trace on
cgtd070 status
```

映射逻辑：

```text
AUX1 < -0.5  → cancel 3BH
-0.5..+0.5  → 不发送命令
AUX1 > +0.5 → track 93H
AUX2上升沿  → center 71H
```

防抖时间100 ms。启动和遥控恢复时只学习当前位置，不立即发命令；必须由
操作者做一次新的开关动作。按住开关或按钮不会重复发送。

状态检查：

```text
cgtd070 status
```

重点字段：

```text
valid=1
AUX1x1000 approximately -1000/0/1000
AUX2x1000 approximately -1000/1000
commands increases on each deliberate action
busy=0
```

## 17. 开机自动启动

手动测试全部通过后，才启用自动启动。PX4支持在SD卡创建：

```text
/fs/microsd/etc/extras.txt
```

在电脑看到的SD卡根目录中对应：

```text
etc/extras.txt
```

内容必须使用Unix LF换行：

```sh
set +e
cgtd070 start -d /dev/ttyS3
set -e
```

这样应用启动失败时不会阻断PX4其他启动流程。重启后检查：

```text
cgtd070 status
```

如果模块尚未编入固件，`extras.txt`中的未知命令可能影响启动，因此必须先
确认`help`中存在`cgtd070`。

## 18. 停止和回退

停止模块：

```text
cgtd070 stop
cgtd070 status
```

应显示：

```text
not running
```

源码回退时，把当前模块移到单独目录，再恢复第6节生成的备份。不要使用
`git reset --hard`覆盖其他人的工程修改。

固件回退可以通过QGC重新烧录之前保存的官方或基线`.px4`文件。

## 19. 常见故障定位

### `cgtd070: command not found`

- 模块未编入固件。
- 板级配置没有`CONFIG_MODULES_CGTD070=y`。
- 烧录了错误的`.px4`文件。

### `cgtd070 status`显示`not running`

- 尚未执行`start`。
- 串口打开或termios配置失败。
- 串口路径错误。

### `TX=0`且写错误增加

- 串口被其他模块占用。
- 串口文件描述符或打开模式异常。
- 选择了错误的设备节点。
- 查看`serial open/read/write errno`确定失败阶段。

### `TX`增加但`RX=0`

- 没有连接吊舱时正常。
- 实物连接时检查吊舱TX到飞控RX、共地、供电、协议接口和波特率。

### `parser bytes`增加但`parser ok=0`

- 数据到达但不符合64字节V2.12反馈帧。
- 检查帧头`FC 2C`、帧尾`F0`、校验和及协议版本。

### `listener cgtd070_status`显示`never published`

- 只有成功解出有效反馈帧才发布。
- 先检查`RX`和`parser ok`。

### 手动命令有效，但遥控器不触发

- 检查`listener input_rc`。
- 检查`RC_MAP_AUX1/2`。
- 检查`listener manual_control_setpoint`中的`valid`、`data_source`和AUX。
- 检查`cgtd070 status`中的`valid`、AUX值、`commands`和`busy`。

## 20. 验收清单

交付或飞行前逐项确认：

- [ ] PX4版本和板级目标已记录。
- [ ] 未修改PX4基线可以正常编译。
- [ ] `cgtd070`模块文件完整。
- [ ] `Cgtd070Status.msg`已注册。
- [ ] 板级配置已启用模块。
- [ ] 自定义固件编译和烧录成功。
- [ ] `help`中存在`cgtd070`。
- [ ] 串口未被MAVLink、GPS或DDS占用。
- [ ] 无吊舱时TX约25 Hz且IO错误为0。
- [ ] 93H、71H、3BH打印帧正确。
- [ ] 实物吊舱RX和`parser ok`持续增加。
- [ ] `cgtd070_status`四项数据正常发布。

- [ ] 遥控器三条命令均为单次边沿触发。

- [ ] 保存了可回退的源码和固件。
